# 说话人分离：界面完成（A 识别按钮 + B 按说话人分组）

## 一、A：会议详情里的「识别说话人」按钮

加在 `TranscriptButtonGroup`（转写面板顶部按钮组）：

- `Users` 图标 + 文案，运行中转圈
- 调用 `diarize_meeting`，成功后 toast 报告识别出几位说话人
- **成功后重新拉取转写**，标签才会显示出来
- 没有转写时禁用（无事可标）

### 顺带把命令签名改成传「文件夹」

原来要传精确的音频文件路径。改成和 `start_retranscription_command` 一致 —— **传文件夹，后端自己找音频**：

```rust
let path = super::recordings::find_audio_file(&folder).ok_or_else(...)?;
```

**理由**：调用方知道的是"哪个会议"，不是"这次录音恰好是 mp3 还是 m4a"。要求前端知道容器格式是没必要的耦合。

## 二、B：转写按说话人分组

### 做法：只在说话人变化时显示标签

```tsx
showSpeaker={!!segment.speaker && segment.speaker !== segments[index - 1]?.speaker}
```

同一个人的连续几段**只在第一段显示名字**，形成视觉分组，而不是每行重复。

### 为什么不用真正的 DOM 分组

转写列表是**虚拟化**的（`@tanstack/react-virtual`）。把行塞进分组容器会破坏虚拟化的高度测量。而「只在变化时显示标签」这个做法：

- **每一行独立决定自己渲染什么**，不依赖邻居的布局 —— 这正是虚拟化需要的
- `showSpeaker` 由父层计算后传入，行组件不需要访问 `segments` 数组

两条渲染路径（虚拟化和简单列表）**用同一条规则**，避免行为分叉。

### 标签本地化

数据库里存的是语言中性的 `speaker_1`，显示时用 i18n 转成「说话人 1」/「Speaker 1」。解析不出编号的标签**原样显示** —— 一个用户看不见的标签比一个难看的标签更糟。

## 三、我这一轮犯了一个严重错误（自己发现并修正）

第一次用脚本添加 handler 时，我**先插入了 import（导致行号后移），然后用了旧的索引** —— 结果 handler 被插到了**函数签名还没结束的位置**，文件结构完全损坏：

```tsx
  }, [meetingId, meetingFolderPath, onRefetchTranscripts, t]);
}: TranscriptButtonGroupProps) {     // ← handler 跑到了签名前面
```

**我是怎么发现的**：插入后我读了插入点附近的内容做校验，立刻看出结构不对。

**怎么修的**：`git checkout --` 从上次提交恢复（那次提交包含我之前全部工作），然后用 `edit` 工具**分 4 个小步骤**重做，每步都 `tsc` 验证。

### 顺带避免了第二个 bug

按行号插入后 `const { t } = useI18n();` 落到了 `useCallback` **之后**，而 `useCallback` 的依赖数组引用了 `t` —— 这是**临时死区（TDZ）的 ReferenceError**，只在运行时抛，`tsc` 不一定报。

我在结构校验里看到 `t`(77) 在 handler(46) 之后，把顺序改正为 `t`(39) → state(40,41) → handler(49)。

**这两个错误都说明同一件事**：脚本化编辑后**必须读取结果校验**，而且**插入操作会改变后续所有索引** —— 不能在一个脚本里混用"先插入前面的内容"和"按旧索引插入后面的内容"。
