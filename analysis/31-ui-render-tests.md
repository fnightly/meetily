# 第 7 轮：把「只有用户能验证」的界面部分也测掉了

## 一、前几轮我一直说「UI 只能靠你看一眼」—— 这个说法不准确

我一直把界面渲染列为「我无法验证」。这一轮发现项目里**已经有现成的组件测试设施**：

- `react-test-renderer` 已安装（`tests/hooks/paginated-transcripts.test.tsx` 在用）
- 测试用 `mock.module` 替换 `@tauri-apps/api/core` 的 `invoke`
- `useI18n` **专门设计了无 Provider 时的回退**，注释写着：

> "can be rendered in isolation (a test, a story) without wiring the provider up"

**所以组件是可以真正渲染出来检查的。**

## 二、先做了一次生产构建

`output: 'export'` 意味着 `next build` 会**为每个页面做预渲染** —— 也就是在 Node 里真正执行一遍组件。任何渲染期崩溃都会让构建失败。

结果：

```
✓ Compiled successfully
✓ Generating static pages (9/9)
无错误标记
```

而且预渲染出的 `settings.html` 里能看到页签栏：

```
返回 设置 通用 录音 词典 转写 纪要 实验功能 界面语言 简体中文 English
```

**「转写」页签在**（我加的说话人分离区块就在这个页签里）。不过非活动页签的内容不会预渲染，所以到这里只能证明「导入和整体结构没问题」。

## 四、过程中发现的一个真实约束

第一次渲染 `VirtualizedTranscriptView` 直接抛错：

```
Error: `Tooltip` must be used within `TooltipProvider`
```

组件内部用了 `Tooltip` 但依赖上层提供的 Provider —— 在应用里是有的（`layout` 层），所以**不是 bug**，但说明**这个组件不能独立渲染**。测试里包一层 `TooltipProvider` 即可。
