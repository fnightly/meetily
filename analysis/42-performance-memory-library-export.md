# 42 · 启动/录音提速、内存优化、记录管理与导出

## 一、启动与录音速度
| 优化 | 实现 | 效果 |
|---|---|---|
| 模型常驻策略 | `audio/transcription/residency.rs`：自动 / 省内存 / 短时常驻 / 始终常驻 | 首次录音不再等模型加载（常驻模式下） |
| 启动后台预加载 | `on_app_start`：数据库初始化后 3 秒在后台加载语音模型（省内存模式除外），不阻塞首屏 | 启动速度不受影响，打开即可录 |
| 悬停预加载 | `usePrewarmSpeechModel`：鼠标悬停/聚焦录音按钮即触发 `transcription_prewarm` | 省内存模式下也能抢出几百毫秒到数秒 |
| 并行准备 | `recording_commands.rs`：模型校验与音频设备准备由串行改为 `tokio::join!` 并行，记录耗时日志 | 开始录音延迟 ≈ max(两者) 而非相加 |

## 二、内存占用
- **自动策略**：内存 ≥16GB 选短时常驻，否则用完即释放。
- **单模型常驻**：切换 Whisper/Parakeet、导入、重新转写前先释放另一个本地引擎，避免两个模型同时驻留（GB 级）。
- **空闲回收**：每 30 秒检查，超过“空闲分钟数”（默认 10）且无任务时自动卸载；使用 try-lock，不与录音争锁。
- **纪要前让位**：启动内置 LLM 生成纪要前释放语音模型（`release_for_heavy_task`）。
- **引用计数保护**：`begin_use()` 守卫 + 活动任务计数，录音/转写中绝不卸载。
- **手动控制**：设置 → 录音 → 语音模型内存策略，可查看当前加载状态、立即预加载/释放内存。

## 三、记录管理（录音库重做）
- 顶部统计：录音数、总时长、占用空间、已转写/已出纪要。
- 搜索：标题即时过滤 + 转写全文搜索（防抖，调用 `api_search_transcripts`）。
- 筛选（带计数）：全部/已转写/未转写/已出纪要/无纪要/缺少音频；排序：最新/最早/时长/大小/名称。
- 按日期分组：今天/昨天/本周/本月/更早。
- 多选、全选；批量导出、批量删除（可选同时删除会议记录）；单行快捷导出。

## 四、导出
- 格式：Word(.docx)、Markdown、TXT(UTF-8 BOM，Windows 记事本不乱码)、HTML（可打印为 PDF）、SRT、WebVTT、JSON。
- 范围：纪要+转写 / 仅纪要 / 仅转写；字幕格式仅含带时间戳的转写。
- 原生保存对话框（单个）/ 文件夹选择（批量），同名自动编号，完成后“打开所在位置”。
- 字段标签随界面语言（中文）；说话人名称与界面一致。
- docx 由前端生成 XML、Rust `zip` 打包，无需额外依赖；已用 LibreOffice 渲染验证（标题、表格、列表、代码、时间戳均正常）。
