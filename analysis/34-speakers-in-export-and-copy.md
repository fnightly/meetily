# 第 10 轮：说话人标签在导出和复制时被丢掉了

## 一、发现的缺口

前面几轮把说话人标签做进了转写列表，但**导出 Markdown** 和**复制到剪贴板**这两条出口没有跟上：

```
meeting-export.ts 里 speaker 出现次数: 0
useCopyOperations.ts 里 speaker 出现次数: 0
```

**结果**：用户在界面上看到「说话人 1 / 说话人 2」，导出成 MD 文件后**这些信息全部消失**。

而「能够导出MD文件」正是你最初明确提的需求之一 —— 导出的文件恰恰是人们会保存和分享的产物。

## 二、根因：同一个概念有四处显示逻辑

| 位置 | 有没有说话人 |
|---|---|
| `VirtualizedTranscriptView`（转写列表） | ✅ 有（第 7 轮加的） |
| `meeting-export.ts`（导出 MD） | ❌ **没有** |
| `useCopyOperations.ts`（复制） | ❌ **没有** |

而标签解析（`speaker_N` → 「说话人 N」）的逻辑**只写在列表组件内部**，另外两处够不着。

## 三、修复：抽出共享模块

新增 `src/lib/speaker-labels.ts`：

```ts
export function speakerNumberOf(label: string): string | null
export function formatSpeakerLabel(label: string, t: Translate): string
export function isStoredSpeakerLabel(label): boolean
```

三处都改用它 —— **导出和列表从此不可能对同一个标签给出不同措辞**。

### 导出：写在每一行

```markdown
**[00:05 · 说话人 1]** 你好
```

列表里是「同一人连续说话只显示一次」的**分组**显示，但文档里**每行都写**：

> 文档会被引用、搜索、重新排序。依赖上一行的标签在这些场景下会丢失 ——
> 而列表里的分组只是阅读辅助。

### 兼容性

无说话人时格式**完全不变**（`**00:05** hello`），所以原有的 20 条导出测试**全部继续通过**。

### 语言

`buildMeetingMarkdown` 接受一个可选的 `speakerLabel` 格式化函数，由 `page-content.tsx` 传入界面的 `t`：

- 导出文件里的措辞与屏幕上一模一样
- `meeting-export.ts` 保持**不依赖界面语言**（纯函数、好测）

## 四、这一轮我犯的错误

复制路径的测试我写错了：用 `limit !== 1` 区分「第一次请求计数」和「第二次请求全部」，但**只有一条转写时两次请求的 `limit` 都是 1**，于是过滤掉了我自己要找的那个。

症状很怪：4 条测试里**第 1、3 条失败，第 2、4 条通过** —— 因为前两条各只有 1 条转写、后两条各 2 条。

我先写了个最小诊断脚本确认 hook 本身没问题（`api defined = object`、请求确实发出），才定位到是测试的过滤条件错了。**改成按顺序取第 0、1 个请求。**
