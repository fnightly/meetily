# 第 9 轮：把唯一没跑过的路径——模型下载——真跑了一遍

## 一、为什么这条路径重要

模型不是随应用打包的，是**按需下载**的（6 MB + 38 MB）。也就是说：

> **在一台干净机器上，下载失败 = 整个功能无法安装。**

而这条路径**从来没有被执行过** —— 你的模型是手动放好的（22:27 那次复制）。之前所有轮次的验证都建立在"模型已存在"这个前提上。

## 二、能测，因为下载函数不依赖 Tauri

```rust
async fn download_one(
    client: &reqwest::Client,
    dir: &Path,
    artifact: &'static catalog::DiarizationArtifact,
) -> Result<(), String>
```

**没有 `AppHandle`** —— 直接可测。它和命令用的是同一个代理感知的 client。

## 三、先确认网络确实可达

```
代理 127.0.0.1:10808      ✅ 在监听
HEAD 请求                 HTTP 200  Content-Length=5992913
```

`5992913` 正是 `SEGMENTATION.exact_bytes` —— 和服务端一致。

## 四、两条测试，真下载

### 1. 下载到最终路径

```
test result: ok. 1 passed; finished in 2.92s
```

断言链：

| 断言 | 保护的东西 |
|---|---|
| 开始时目录为空、且被报告为 missing | 通过不是因为"文件本来就在" |
| 文件落在**最终路径** | 不是 `.partial` |
| 体积**精确等于** `exact_bytes` | 截断的响应不会被存下来 |
| **没有 `.partial` 残留** | 残留文件会被当成可用模型 |
| 下载后不再被报告为 missing | 目录扫描逻辑一致 |
| **但整体仍不 ready** | 只有两个之一不算可用集合 —— 否则会让一次运行启动后在第二个模型上失败 |

### 2. 覆盖已存在的损坏文件

```
test result: ok. 1 passed; finished in 1.83s
```

界面上提供的「重新下载」正是**截断文件的补救手段**，所以目标已存在时必须能成功。测试先写入 `b"not a model"`，下载后验证体积恢复为 `exact_bytes`。

## 五、为什么这两条是 `#[ignore]`

它们需要网络、要下 6 MB。放进常规套件会让离线环境和 CI 变慢且不稳定。但它们**不是可以删的**：模型下载是唯一让功能可用的入口，值得有一条能手动跑的真实验证。
